# Цикл работы

Веток нет, PR нет. Работаем в `main`. Контроль стоит в двух местах — пуш и деплой — плюс
гейт перед каждым коммитом.

## Обычный день

1. **Задача от владельца.** Непонятное спрашивается сразу и одним сообщением, с живым
   примером вариантов. То, что можно узнать из кода или логов, не спрашивается.
2. **Разведка** — агентом `explorer`, тесты — `test-writer`, чтобы тяжёлое чтение не
   съедало основной контекст. Длинные задачи — со списком шагов, по которому идёшь.
3. **Гейт и коммит — сами** (`/finish`): гейт → ревью → доки и `CHANGELOG` → блок «Как
   проверить» → чистый локальный коммит.
4. **Наружу — по слову.** `push` отправляет на GitHub и запускает CI. `release` катит на
   сервер.

## Push против деплоя

| Действие      | Что значит                    | Чем открывается                                                         |
| ------------- | ----------------------------- | ----------------------------------------------------------------------- |
| `git commit`  | локальный савпоинт            | свободно (блокируется, только если опасно или с припиской)              |
| `git push`    | код на GitHub, **прогон CI**  | `/push`: зелёный гейт → `.approve-push`                                 |
| пуш тега `v*` | **деплой на прод**            | `/release`: строгий гейт → версия → подтверждение → `.approve-release`  |

Маркеры одноразовые и живут 15 минут: одобрение за вчерашний зелёный гейт не должно
тратиться на сегодняшнее непроверенное изменение.

## Деплой

1. `/release` → договорились о `patch` / `minor` / `major`.
2. `## Unreleased` в `CHANGELOG.md` заполнен и закоммичен.
3. `python scripts/gate.py --strict`.
4. `python scripts/release.py --bump <kind> --dry-run`, затем без `--dry-run`: `VERSION`,
   зеркала, `CHANGELOG`, коммит `chore(release): vX.Y.Z`, локальный тег, маркеры.
5. «Го» → `git push origin main`, `git push origin vX.Y.Z`.
6. CD: гейт ещё раз → сборка образа в GHCR → `docker compose up -d` на сервере.
7. Проверка: `gh run list`, `scripts\prod.bat health` (новая версия в ответе),
   `scripts\prod.bat logs zebaro-core-bot 10m`.

Пошло не так — **катимся вперёд**: чиним, `--bump patch`, выкатываем снова.

## Когда планировать, а когда просто делать

По умолчанию — просто делать. Остановиться и показать подход стоит, когда:

- есть развилка, где варианты дают разный продукт (что присылать, как оценивать вакансии,
  как выглядит сообщение);
- изменение трогает данные в MongoDB, которые уже лежат на проде;
- ты собираешься отойти от правил `CLAUDE.md`.

## Нашёл постороннее

Всё, что заметил и что **не является текущей задачей**: **спроси владельца одной
строкой** — делаем сейчас или в заметки. «Нет» или спросить не вышло → `/idea` →
`_ideas/`. Никогда не решай в одиночку и никогда не давай этому испариться.
